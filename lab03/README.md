## Система уведомлений
**Паттерн проектирования:** Шаблонный метод (Template Method)

---

## 1. Описание предметной области

Система уведомлений — это приложение, предназначенное для отправки сообщений пользователю через различные каналы связи, такие как электронная почта, Telegram и SMS(заглушка). Пользователь указывает получателя, тему и текст сообщения, после чего система выполняет отправку через выбранный канал.

---

## 2. Описание проблемы

При наивной реализации каждый канал уведомлений реализует полный процесс отправки отдельно: формирование сообщения, проверку получателя, отправку и логирование результата. Это приводит к следующим проблемам:

- Дублирование кода — один и тот же алгоритм повторяется в каждом классе отправки.
- Сложность поддержки — при изменении общего процесса необходимо вносить изменения во все реализации.
- Плохая расширяемость — добавление нового канала требует копирования и модификации существующего кода.
---

## 3. Решение с помощью паттерна Шаблонный метод

Паттерн Template Method решает проблему путём выделения общего алгоритма отправки уведомления в базовый класс.

Общий процесс реализован в методе `send_notification()` класса `NotificationSender` и включает последовательность шагов:

| Шаг алгоритма | Реализация |
|---|---|
| Формирование сообщения | Реализовано в базовом классе (`format_message()`) |
| Проверка получателя | Переопределяется в подклассах (`validate_recipient()`) |
| Отправка сообщения | Переопределяется в подклассах (`send()`) |
| Логирование результата | Реализовано в базовом классе (`log()`) |

Базовый класс задаёт фиксированную структуру алгоритма, а конкретные классы (`EmailSender`, `TelegramSender`, `SmsSender`) реализуют только изменяемые части.

Таким образом, общий процесс остаётся неизменным, а различия между каналами инкапсулируются в отдельных классах.

## 5. Вывод
Использование паттерна Шаблонный метод позволило устранить дублирование кода и выделить общий алгоритм отправки уведомлений в одном месте. Архитектура приложения стала более понятной и структурированной.
Внедрение паттерна позволяет облегчить добавление новых каналов уведомлений не требуя изменения существующего алгоритма — достаточно реализовать новый класс с нужной логикой отправки.
