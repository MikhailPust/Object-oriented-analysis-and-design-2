 Паттерн : Загрузка по требованию (Lazy Load)

### 1. Описание предметной области

Каталог вакансий  — это десктопное приложение, предназначенное для просмотра вакансий. 

### 2. Описание проблемы

При наивной реализации (так называемой «жадной загрузке») приложение при запуске выполняет один тяжеловесный SQL-запрос. Этот запрос извлекает абсолютно все данные из базы данных (включая многострочные описания и требования для всех существующих вакансий) и сразу сохраняет их в оперативной памяти компьютера. Это приводит к следующим проблемам:

* **Долгий запуск приложения** — чтение и передача большого объема тяжелых текстовых данных по сети замедляет первоначальную отрисовку интерфейса.
* **Высокое потребление оперативной памяти (RAM)** — с увеличением данных в бд в память загружаются детали тысяч вакансий, хотя за одну сессию пользователь не всегда смотрит их все. Большая часть загруженных данных остается невостребованной.

### 3. Решение с помощью паттерна Загрузка по требованию

Паттерн «Загрузка по требованию» решает проблему путем разделения сущности на «легкую» (базовая информация) и «тяжелую» (детали) части, откладывая ресурсоемкий запрос к базе данных до момента фактического обращения пользователя к тяжелым данным.

Процесс реализован внутри класса `Vacancy`, где детальная информация вынесена в отдельный класс `VacancyDetails`. При старте приложения загружаются только базовые данные для списка. Логика отложенной инициализации инкапсулирована (скрыта) в методе `getDetails()`, который работает по следующему алгоритму:

| Шаг алгоритма | Реализация в коде |
| :--- | :--- |
| **Инициализация списка** | Метод `loadAllVacancies()` получает из БД только легкие поля (ID, заголовок, компания). Скрытое поле `details` внутри объекта инициализируется как `null`. |
| **Обращение к данным** | Интерфейс запрашивает детали выбранной вакансии через метод `getDetails()`. |
| **Проверка наличия данных** | Внутри метода объект `Vacancy` проверяет сам себя: `if (this.details == null)`. |
| **Загрузка по требованию** | Если данных нет, выполняется точечный SQL-запрос `loadDetailsFromDb(this.id)` только для одной конкретной вакансии. |
| **Кэширование** | Полученные данные сохраняются в поле `this.details`, чтобы при повторном клике на ту же вакансию мгновенно отдать их из памяти без обращения к БД. |

Таким образом, объект `Vacancy` выступает в роли «умного заместителя» (Proxy): интерфейс не знает, загружены ли данные — он просто запрашивает детали, а объект самостоятельно решает, взять их из кэша или запросить у сервера.

### 5. Вывод

Использование паттерна «Загрузка по требованию» позволило кардинально снизить потребление оперативной памяти и ускорить время холодного старта приложения. Архитектура стала более масштабируемой и оптимальной: теперь система может без проблем выводить списки из десятков тысяч вакансий, так как тяжеловесные текстовые данные скачиваются точечно и исключительно по инициативе пользователя (при клике). Добавление встроенного механизма внутреннего кэширования внутри паттерна обеспечило мгновенный отклик интерфейса при повторном обращении к уже просмотренным позициям каталога.
